# X 스페이스 무료 감지와 시작 알림

**Decisions:** `DEC-20260919-hololive-x-spaces` (governing), `DEC-20260919-x-spaces-admin-reconnect` (governing)

## Execution capsule

**Goal:** 로그인 쿠키 기반 X 내부 API로 멤버가 직접 연 스페이스를 발견하고 방송 구독 방에 시작 링크를 보냅니다.
**Context:** 기존 alarm-worker와 PostgreSQL dispatch ledger를 사용합니다. 작업 트리는 /home/kapu/work/hololive-xspaces-20260919/hololive-bot 입니다.
**Constraints:** 유료 API·외부 유료 서비스 금지. 실계정 세션 연결과 발송 설정까지 사용자 승인 범위입니다. 설정 전 기본 비활성화, 시작 알림만, 게스트 참여·녹음 제외. 세션 원본은 사용자의 윈도우 Edge이며 쿠키 값을 대화·로그에 노출하지 않습니다.
**Evidence:** twspace-crawler b03071c6의 avatar_content 및 AudioSpaceById 구현, 기존 domain/alarm과 dispatchoutbox 소유 경로를 확인했습니다.
**Success:** 계정→스페이스 발견, 호스트 확인, 방별 지속 중복 방지, 오류/미상 보존, 쿠키 비노출이 모의 응답과 기존 발송 경로 검사로 검증됩니다.
**Output:** 무료 수집 helper, worker 연결, 전용 source payload와 텍스트 렌더링, 테스트, 실계정 세션·발송 설정, 사용 문서와 검증 기록.

## Implementation

### T01 수집 경로 구현

alarm-worker/xspaces 소유 Node helper에서 사용자 ID 목록과 cookie를 stdin으로 받습니다. X 웹 내부 경로만 허용하며 조회 timeout·출력 크기·redirect를 제한합니다. twspace-crawler의 전체 녹음/알림 런타임 대신 그 요청 생성에 쓰이는 x-client-transaction-id 0.3.1의 공개 API를 재사용합니다. 공식 API 자격 증명은 받지 않습니다. 일반 API 장애를 빈 목록으로 변환하지 않습니다. AC01/V01과 연결됩니다.

### T02 기존 발송 경로 연결

T01 이후 shared domain에 x_space source, worker에 poll runner를 추가합니다. 명시적 X 사용자 ID↔YouTube 채널 ID 매핑을 사용하고 기존 LIVE 구독자를 조회합니다. 스페이스 ID로 이벤트, 방 ID로 delivery를 식별합니다. title 변경/재시작에도 첫 관측 payload를 보존하는 원장을 소유하여 충돌을 피합니다. 개설자만 대상이며 새 플랫폼을 YouTube 방송으로 위장하지 않습니다. AC02/V02와 연결됩니다.

### T03 런타임과 문서 검증

T02 이후 기본 비활성화 설정, worker 수명주기, helper 실행 파일 배치와 사용 문서를 연결합니다. cookie는 DB에 인증 암호화로 보관하며 키 파일은 기존 static secret 절차를 따릅니다. 값·응답 원문은 로그에 넣지 않습니다. 수집 실패는 오류로 관측하고 발송 재시도/미상 계약은 기존 ledger를 따릅니다. AC03/V03과 연결됩니다.

### T04 실계정 세션과 발송 설정

T03 이후 사용자 윈도우 Edge의 지정 세션을 비밀 관리 절차로 연결하고 사용자 지정 검증 방에 발송을 검증합니다. 봇의 세션 만료·무효화·재인증 조건을 확인하며, 고정 쿠키 복사만으로 무인 장기 운영을 보장하지 않습니다. 지정 세션의 안전한 전달과 검증 방이 정해지기 전에는 임의 계정·방을 선택하지 않습니다. AC04/V04와 연결됩니다.

### T05 관리자 재연결 구현

T03과 병행하여 Iris Admin의 기존 Hololive 세션·권한·CSRF·mutation ID 보호 경로에 상태 조회와 세션 교체 요청을 추가합니다. 별도 작업 트리는 /home/kapu/work/hololive-xspaces-20260919/iris-admin 입니다. 새 cookie는 암호화된 후보로 저장하고 worker에서 검증 성공 시에만 기존 인증을 교체합니다. 실패한 후보는 기존 인증을 지우지 않습니다. generation 비교로 오래된 관측이 새 인증을 덮어쓰지 않게 합니다. 화면은 마지막 성공·인증 필요·후보 검증 상태와 복구 방법을 표시하며 secret 재조회와 브라우저 영속 저장은 금지합니다. T04는 T05 이후 완료합니다. AC05/V05와 연결됩니다.

### T06 스페이스 알림 양식 통일

T02 완료 후 스페이스 전용 DB 템플릿과 샘플을 등록하고 기존 렌더러의 mdsafe 처리를 재사용합니다. 방송 시작 알림과 같은 빨간 원·굵은 멤버명·제목 링크를 사용하며 제목이 없으면 URL만 표시합니다. 구독·중복 방지·전송 경로는 유지합니다. 현재 운영 API의 다른 작업 변경을 보존하고 마이그레이션과 워커만 반영합니다. AC06/V06과 연결됩니다.

## Acceptance

### AC01 비용 없는 발견

계정 ID에서 현재 스페이스를 발견하며 공식 API/유료 공급자 경로가 없습니다. 응답 이상, 인증·제한 오류가 오프라인으로 바뀌지 않습니다.

### AC02 중복 없는 시작 알림

호스트의 방송 구독 방에만 스페이스 링크를 전달합니다. 반복 관측·재시작·제목 변경으로 중복 발송하거나 기존 YouTube 발송에 섞이지 않습니다.

### AC03 안전한 실행과 비활성 기본값

설정 미지정 시 외부 요청/프로세스가 없고 종료 시 helper를 회수합니다. secret 값은 인자·로그·검증 산출물에 없습니다.

### AC04 실계정과 발송 검증

지정 X 계정의 인증으로 실제 감지를 확인하고 지정 방에 발송을 검증합니다. 봇 인증 유지의 확인된 범위와 재인증이 필요한 조건을 명시합니다.

### AC05 관리자에서 재연결

권한 있는 사용자가 Iris Admin에서 새 세션을 제출하고 검증 결과를 조회할 수 있습니다. 실패 시 기존 세션 보존, stale 관측 차단, secret 응답·로그·브라우저 저장 비노출을 검사합니다.

### AC06 기존 알림 컨벤션 준수

스페이스 알림은 전용 DB 템플릿으로 렌더링되며 멤버명과 제목의 Markdown 특수문자를 무력화합니다. 제목 유무와 사용자 정의 템플릿을 지원하고 템플릿 누락은 오류로 보존합니다. 기존 방송 구독과 전송 경로는 바뀌지 않습니다.
