### 3.2 운영 Vertex AI · Decisions API 실호출 검증 결론
상세 표는 원 계획 문서 `## 추가 실호출 검증`에 기록되어 있으며 핵심 결론만 추리면 다음과 같다.

1. **추론 레벨 지원 범위:** `ThinkingLevelMinimal`은 `hydrogen`·`argon`·`carbon` 모두 HTTP 400 `Thinking level is unsupported: THINKING_LEVEL_MINIMAL`로 거부된다(`LOW`·`MEDIUM`·`HIGH`만 지원).
2. **모델 × 추론 레벨 권장 조합:**
   - **포스터 행 추출:** `gemini-4-hydrogen` `LOW` (슬롯 정확도 76/76, 평균 7.92~9.20초, 장당 $0.011; `argon`은 Vertex 이미지 지연 104초, `carbon`은 `LOW`·`HIGH` 504 및 `MEDIUM` `熱千`→`熱干` 오독으로 기각).

   - **X 원글 행 대응 추출 (`match`):** `gemini-4-hydrogen` `LOW` 확정 (27건 전수 시험에서 `LOW`·`MEDIUM`·`HIGH` 판정 분포 `시각변경 5, 확정 2, 미정으로 1, 항목 없음 1, 같음 23`이 100% 동일하고 Go 검증 거절 0건, 평균 4.80초, 건당 $0.011).
3. **Decisions API (`POST https://generativelanguage.googleapis.com/v1beta/decisions`) 필수 구현 규칙:**
   - 선택지 설명 키는 `choices`가 아닌 **`criteria`**(`noul`은 `true_description`/`false_description`, `choice`는 옵션 키별 설명).
   - 빈 문자열 입력은 HTTP 400 `Missing text in content of type text.`를 반환하므로 텍스트 없는 글은 호출 전 건너뛴다.
   - HTTP 400 오류 본문은 백엔드 오류(`{"error":{"code":"safety","message":"..."}}`, 문자열 `code`)와 Google API Gateway 오류(`{"error":{"code":400,"status":"INVALID_ARGUMENT","message":"..."}}`, 정수 `code`) 두 가지이므로 파서가 둘 다 처리해야 한다.
   - 통과 기준은 단일 `kind` 확률이 아닌 **`schedule_info.noul >= 0.7 && kind.choice ∉ {"other", "weekly"}`** 결합 규칙을 쓴다(변경 겸 일일 공지가 `change:0.65`+`announce:0.30`으로 분할되는 사례 해결).
4. **FxTwitter 셀프 리포스트(Self-RT) 처리:**
   - 쿄코가 본인 방송 공지를 셀프 리포스트해 타임라인 배열 앞쪽에 `reposted_by != null` 항목이 오고 원본(`reposted_by == null`)이 뒤나 2페이지로 밀린다.
   - `seen[id]` 중복 제거를 `item.original()` 판정 뒤에 두고 최대 2페이지(확정 포스터 게시 시각 이전 원글 도달 시 조기 중단)를 읽어야 공지 누락을 막을 수 있다(실측에서 16건 복원 확인).
5. **Vertex AI 동시성:** 병렬 호출 시 `429 RESOURCE_EXHAUSTED`가 발생하므로 순차 처리 + 지수 백오프 재시도를 유지한다.

**추출 (`extract.txt`)**
- 행: `date`, `start`(24시 이상은 그대로), `end`, `tz`(인쇄된 그대로), `status`(`planned`/`tentative`/`cancelled`/`off`), `text`(줄을 " / "로 연결, 모든 시간대의 시각은 제외), `badges[]`.
- 내용이나 장소(누구 채널인지)만 불확실하면 `planned`, 방송 여부·시각이 열려 있거나 시각이 근사(頃, 以降)면 `tentative`. 그 칸에서 열리지 않는 방송(취소·이동)은 `cancelled`이고, 같은 날 시각만 바뀐 칸은 취소가 아니며 새 시각으로 적고 상태는 나머지 정의로 정한다. 범례가 이름 붙인 아이콘은 범례 글자로 `badges`에 넣는다. 그림으로만 표시된 참여자는 `(pictures)`.

**대응 (`match.txt`, 모델로 시험할 자료 없음)**

**연결 계약 (코드 책임)**
- 번역 입력 행은 `N. <text>` 뒤에 위 표지를 붙인다. `Poster time zone`은 추출 `tz`에서 정한다.
- 대응 항목의 `text`가 비면 번역하지 않는다: `off`는 코드가 "휴방"(같은 날 여러 행이면 하나로 합침), `cancelled`는 기존 한국어 칸을 두고 취소로 표시, 시각만 바뀌면 기존 칸 유지. 휴방 행에 대응된 `planned`·`tentative` 항목은 코드가 제목을 "방송"으로 쓴다.
- `text`가 있으면: 대응된 행이 있을 때 `N. <저장된 행 원문과 표지> [update: <text>]` 한 행 묶음으로 번역하고 update를 행 원문 뒤에 누적 저장한다. 대응된 행이 휴방 행이거나 `row`가 null이면 `N. <text>`만 번역한다.
- 대응 항목의 날짜가 주 범위 밖이면 이번 주 카드에서는 취소로 표시한다.
- 카드 부연 줄은 코드가 `<with_ko를 " · "로 이음>와/과 함께` · `<place_ko>에서` · `note_ko` 순으로 만든다. 조사는 도우미로 고른다(한글 받침, 로마자·숫자는 읽는 소리, 괄호 안 역할은 무시). 마지막 항목 "그 외 참가자"는 "… 등과 함께"로 그린다. `tags_ko`는 작은 딱지다(V5에서 뺀 EN/JP 표기의 복원 경로). 취소 표시는 카드 시안에 아직 없다.

### 4.1 반드시 유지하는 표기 원칙

### 4.4 표시 규칙 (모든 테마 공통, `layout.go`)
- 제목 끝의 괄호 부연은 본제목과 나눠 작은 글씨로 쓴다. 한 줄에 들어가면 옆에, 넘치면 아랫줄에 둔다.
- 시각 표시는 `timeLabel`의 4종이다.
  - 확정: 글자 그대로(쿄코는 검정 캡슐, 메라는 크림 딱지).
  - 미확정(시각 없음 `미정`, 미정 상태인데 시각 있음 `21:00 ?`): 점선 캡슐.
  - 내용만 변경(시각 같음): 강조색 시각(츠즈리 빨강 글자, 소피아 노란 형광펜, 쿄코 주황 캡슐, 메라 분홍 딱지).
  - 시각 변경: 강조 캡슐 안에 `이전 → 현재`. 미정으로 바뀌면 `21:30 → 미정`.
- 휴방은 테마별 휴방 표시, 일정이 없는 날은 빈 칸으로 남긴다(주 범위 7일을 항상 그린다).
- 글자 맞춤(`fitTable`): 일정이 적으면 배율 1.12(세로형 1.24)까지 키우되 본제목 줄 수가 늘면 키우지 않는다. 넘치면 0.86까지는 제목이 잘리지 않는 배율을 찾고, 그 아래로는 하루 여러 건인 날을 건당 한 줄로 줄인 뒤 0.62까지 줄인다.
- 쿄코(`kyokoFit`): 단별로 칸 높이를 내용만큼 잡고 남는 높이를 건수에 비례해 나눈다. 날짜가 적은 단에는 도장 칸 자리를 남긴다. 넓은 변경 캡슐 옆에서 제목이 접히면 캡슐을 제목 위로 올린다.
- 메라(`melaTitle`): 캡슐마다 배율을 0.8까지 찾고, 없으면 한 줄로 줄여 부연부터 말줄임한다.

### 4.6 본 구현으로 옮길 때의 메모
- 프로토타입은 `font.Face` 대신 `sfnt` 글리프 윤곽을 `vector.Rasterizer`로 직접 채운다(회전·외곽선에 같은 경로 사용). `sfnt.Buffer`와 글리프 캐시를 공유하므로 기존 `render.fontMu`와 같은 직렬화가 여전히 필요하다.
- 글꼴 7종을 `go:embed`하면 바이너리가 약 13MB 는다. OFL 원문을 함께 넣어야 한다. 크기가 문제면 한글 2,350자 서브셋을 검토한다(없는 글자는 `Pretendard Bold`로 대체되는 경로가 이미 있다). `Pretendard-SemiBold` 편입은 필요 없어졌다.
- 표제 글꼴에 없는 기호(`★`, `·`, `→`, `–`)는 `Pretendard Bold` 글리프로 대체된다.
- `!스케쥴` 응답은 (확정 포스터, 마지막 변경 시각, 판형) 기준 캐시가 필요하다.
- 프로토타입은 `go vet`·`gofmt`만 통과시켰다. 저장소 golangci-lint·NilAway 기준과 단위 테스트는 이식 때 맞춘다.

### 4.7 남은 확인 사항
- **사용자 디자인 확인**과 **판형 선택**이 아직 없다. 세로형(3:4)이 휴대폰에서 가장 크게 읽히고, 16:9는 원본 포스터와 같은 비율이다.
- 갤러리 페이지의 브라우저 스크린샷 검증은 세션의 브라우저 도구 기동 실패로 하지 못했다. PNG는 직접 열어 확인했고(16:9·3:4 원본 크기, 4:3과 한계 확인용은 축소 격자), 갤러리 자산 33개는 HTTP 200을 확인했다.
- 실제 카카오톡 표시는 확인하지 않았다.
- 카드 제목은 최종 프롬프트의 번역 출력이다(§3.5). 변경 공지로 내용이 바뀐 행 3건(츠즈리 11/11, 11/12, 11/14 21:30)은 이전 문구 그대로다.
