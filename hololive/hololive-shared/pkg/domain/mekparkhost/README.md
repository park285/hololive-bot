# mekPark 방송자 표시와 UNIT B 멤버별 구독

`Identify(channelID, title)`는 UNIT B와 ACHRORA 공유 채널의 제목에서 확인된 진행자와
게스트를 반환한다. `Result.Label()`은 인물 표시를 만들고 `DisplayName`은 기존 유닛 이름에
이를 붙인다. 외부 조회와 상태 변경은 없으며 수집·구독·DB의 채널 정체성을 바꾸지 않는다.

`rules.json`이 채널, 멤버 이름, 개인 태그와 시리즈 이름의 정본이다. 이 파일은 바이너리에
포함되므로 수정 후에는 새 빌드가 필요하다. 잘못된 JSON은 테스트 및 최초 로드에서 실패한다.
성명과 별도 태그를 중복 등록하지 않으며, 정규화에는 이미 사용 중인 `golang.org/x/text`의
NFKC를 사용한다. 의존성 버전은 변경하지 않는다.

## 판별 범위

- 유닛은 두 채널 ID로만 결정한다. 다른 채널에 이름이나 유닛 태그가 있어도 개인을 표시하지 않는다.
- 성명과 개인 방송 태그를 찾는다. NFKC, 제로폭 문자 제거, 해시 뒤 공백 정리를 먼저 적용한다.
- `あさやなストレッチ夏` 시리즈는 사야나를 진행자로 두며, 다른 식별 인물은 같은 유닛이어도 게스트다.
- 시리즈가 없으면 채널에 속한 식별 인물을 진행자로, 다른 유닛 인물을 게스트로 구분한다.
- 이름 일부는 `視点`·`パート`와 검증한 `りらら×ミラ` 쌍에서만 사용한다. `ミラクル`,
  일반 본문의 `ひなみ`, 별명 `赤たん`, 팬 이모지, 단체·노래·게임 이름은 개인 식별 근거로 쓰지 않는다.
- 진행자가 없으면 인물 표시는 비워 둔다. 따라서 `?`, 단체 공지, 식별되지 않은 릴레이 방송을
  임의의 한 사람에게 배정하지 않는다. 단체 전체 멤버를 자동으로 나열하지도 않는다.
- `Participant.Evidence`에는 정규화 후 일치한 성명·태그·시점/파트·이름 쌍을 남긴다.
  확률이나 정확도 점수로 해석하지 않는다.

## 표시 경로

단일 알림은 `유닛 B · 미라`, 시리즈 게스트는 `아크로라 · 사야나 (게스트: 미라)`처럼 표시한다.
텍스트와 카카오링크의 진행자 표시에 같은 판별기를 사용한다. 묶음 알림과 채널 일정은 개별 항목에
인물을 붙이고, 묶음 전체의 유닛 이름은 유지한다. 라이브·예정 방송 목록과 방송 이력에도 적용한다.
표시 경로는 Stream·Channel·outbox payload·원본 제목을 수정하지 않는다.

## UNIT B 멤버별 구독

구독 주체는 채팅방이다. 같은 방에서 라이라·미라·네온을 각각 등록하고 알림 종류도 따로
선택할 수 있다. 실제 YouTube 채널 ID는 유지하고, 구독에만 별도의 `host_id`를 저장한다.
`host_id`가 비어 있으면 기존 UNIT B 전체 채널 구독이다.
멤버별 구독의 추가·해지 응답과 목록은 `미라[유닛b]`처럼 소속을 함께 표시한다.

다음 명령 앞에는 봇에 설정된 명령 접두사를 붙인다.

| 명령 | 동작 |
|---|---|
| `알람 추가 미라 방송` | 미라의 방송 알림을 구독한다. |
| `알람 추가 네온 쇼츠` | 네온의 쇼츠 알림을 별도로 구독한다. |
| `알람 제거 미라 방송` | 미라의 방송 구독만 해지한다. |
| `알람 추가 유닛 B` | UNIT B 전체 채널을 구독한다. |
| `알람 목록` | 멤버별 구독과 알림 종류를 확인한다. |

제목에서 진행자를 확인하면 해당 멤버 구독 방과 전체 채널 구독 방에 알린다. 공동 진행자는
각 멤버의 구독 방을 합치며, 같은 방에는 한 번만 알린다. 진행자를 특정하지 못한 제목이나
빈 제목은 **fail-open**으로 처리해 해당 알림 종류를 구독한 UNIT B의 모든 방에 알린다.
다른 채널이나 비구독 방으로 대상을 넓히지는 않는다.

전체 채널 구독을 해지해도 별도로 등록한 멤버 구독은 남는다. 목록과 추가 응답에는 다른
멤버로 확인된 다음 방송을 표시하지 않는다. ACHRORA의 멤버별 구독은 이 변경에 포함하지 않는다.

구독 조회 실패나 손상된 이벤트 payload는 기존 오류·재시도 경로로 보낸다. 이를 진행자 미상으로
간주하지 않는다. 상세 검증과 운영 적용 조건은
[구독 변경 보고서](../../../../../docs/review/unit-b-member-subscriptions-20260906.md)에 기록한다.

## 표본과 한계

`testdata/title_corpus.json`은 2026-08-28의 149개 표본에 2026-09-06의 46개 신규 표본을
추가한 자료다. `hololive-osaka`의 `hololive` DB에서 `default_transaction_read_only=on`을
설정하고 `transaction_read_only=on`을 확인한 뒤 두 채널만 제한 조회했다. 같은 video_id가
`youtube_live_sessions`와 `youtube_videos`에 있으면 세션 쪽을 사용한다.

제목을 읽어 정리한 기대값을 사용한다. 기존 자료의 같은 유닛 게스트 2건을 바로잡았고,
새 자료의 같은 상황 1건도 진행자/게스트로 나눴다. `kind=unspecified`는 개인 식별을
보류한 상태이며 단체 방송과 개인 미상, 비방송 콘텐츠를 모두 포함한다.

| 출처 | 표본 | 진행자 식별 기대값 | 개인 식별 보류 |
|---|---:|---:|---:|
| 방송 세션 | 140 | 129 | 11 |
| 세션과 겹치지 않는 영상·쇼츠 | 55 | 46 | 9 |

이 수치는 제목 근거의 판별 범위이며 실제 출연자를 맞힌 정확도가 아니다. 방송 세션에는 데모와
커버 영상도 들어 있다. 모든 제목의 영상을 독립적으로 확인한 학습 정답 자료가 아니며,
저장된 제목은 방송 전 알림 시점 이후 수정되었을 수 있다. 모델을 비교하려면 별도로 검수한
진행자·게스트 정답과 알림 시점 제목을 확보하고 video_id 및 시간 기준으로 학습/평가 자료를
분리해야 한다. 근거가 없는 제목을 모델의 추측으로 확정하는 동작은 구현하지 않는다.

저장소 루트에서 `go test -race -v ./hololive/hololive-shared/pkg/domain/mekparkhost`를 실행하면
표본과 오탐 회귀를 검증하고 출처별 판별 범위를 출력한다.

공개 YouTube 제목을 추가한 오프라인 모델 학습과 비교는
[`scripts/experiments/mekpark-host`](../../../../../scripts/experiments/mekpark-host/README.md)에 있다.
이 실험은 현재 판별기나 운영 표시를 바꾸지 않는다.
